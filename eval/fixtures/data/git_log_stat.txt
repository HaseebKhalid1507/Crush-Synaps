    globset: match filename-only regexes against basenames
    
    We now match filename-only globs such as **/.venv* and **/*.py[cod]
    against the basename, avoiding a regex search over the full path. We
    use this strategy only when the filename pattern cannot match a path
    separator.
    
    On Linux x86-64 against 3fce3b5, building the Python ignore rules is
    about 23% faster. Warm incremental replay over Ruff paths improves
    4–9%; replay over uv paths is flat in the default build and improves
    2–4% with fat LTO. The default-build Ruff parallel walk is 3.7%
    slower.

    ignore: use byte keys for incremental parent lookups
    
    We now store incremental directory-cache keys as OsString values to
    avoid path-component hashing. On Unix, we find a cached parent by
    scanning path bytes before parsing components. Cache misses fall back
    to the component walk, preserving alternate path spellings and cached
    ignore-file snapshots.
    
    On Linux x86-64 against 3fce3b5, warm incremental replay over Ruff
    and uv path sets improves 12–13% and 15–18%, respectively, across
    default and fat-LTO builds; ignored-parent checks improve about 68%.
    Paths with an internal ./ are 0.5–2.2% slower.
    
    PR #3559

    globset: reject impossible literal lengths before hashing
    
    We now skip literal hash lookups when the byte length of a path or
    basename cannot match any literal. We track lengths modulo 64 in a bit
    mask, so collisions still go through the exact lookup. The full-path
    and basename strategies now share the same implementation.
    
    On Linux x86-64 against 3fce3b5, warm incremental replay of Ruff and uv
    path sets improves 9–14% across default and fat-LTO builds, and Ruff
    serial walks improve 3.6–5.1%. The default-build uv parallel walk is
    3.5% slower, and fat-LTO single-rule construction increases from 379 ns
    to 387 ns.
    
    PR #3558
